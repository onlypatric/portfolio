# ohmygui input

This folder implements the 28 input/control entries listed in `swiftui-web-component-blueprint/catalog/ALL-COMPONENTS.md` under `03-input`.

`ButtonGroup` is an additional control, exported from this barrel and implemented beside Button in `../control/button/ButtonGroup.tsx`. It joins related actions with logical outer corners and separators. Props: `orientation` (horizontal/vertical), `radius` (Button radii), `size`, `variant`, `fullWidth`, and `disabled`. Child size/variant overrides win; group disabling always disables every child. Native Tab/Space/Enter behavior, refs, handlers, loading, and ripple feedback remain owned by each Button; this is not a single-selection picker.

Children must be OhMyGUI Buttons (including arrays, fragments, and conditional empty children). A compatible wrapper can explicitly opt in with `data-ui-button=""`; it must render one native button and forward className, size, variant, disabled, and native button props. Arbitrary elements/text throw a descriptive error. Label the group using `aria-label` or `aria-labelledby`. Group corners intentionally override child radii. The API follows the composition intent of [HeroUI ButtonGroup](https://heroui.com/en/docs/react/components/button-group), without importing its implementation.

Native controls retain browser form semantics and attributes. Enhanced controls use React state only where the catalog calls for filtering, reveal, sharing, clipboard access, rename flow, refresh, or other browser behavior. The public barrel is `./index`.

## Family refinement

The original 29-component refinement and its per-component evidence are recorded in [the acceptance record](../../../../../swiftui-web-component-blueprint/INPUT-REFINEMENT.md). Those browser results cover the earlier family phase. The custom Picker/popup-motion follow-up below was verified by source review and typecheck only, as requested; do not treat previous browser results as certification of the new implementation.

TextField, SecureField, SearchField, TextEditor, DatePicker and Picker now share an explicit label/control/message frame. They support label, helperText/error, startContent/endContent and native control refs. Controls/adornment buttons sit outside the associated label; native name/value/autocomplete/required/min/max/disabled/readOnly semantics remain on the input/select/textarea. Errors take precedence over hints and merge, rather than overwrite, aria-describedby targets. Prefix/suffix layout follows RTL and does not absolutely overlap text. Focus/error motion uses shared tokens and the reduced-motion override; there are no input animation frame loops.

For these six controls, wrapperProps now describes the outer div (including its events/styles); classNames.root/label/control/input/hint/startContent/endContent style individual parts. This deliberately replaces the old enclosing label so reveal/action buttons do not create ambiguous labeling. Use label or native aria-label/aria-labelledby, not a placeholder as the sole name. Existing className/style/ref still target the native control. Prefer the built-in label prop over adding an external wrapping label.

SecureField reveal is disabled with the field, keeps the same native input/value, preserves a pointer user's caret/focus, leaves keyboard focus on the button, and returns to password type on form reset. No password is copied to extra state, persisted or logged. FieldGroup generates its hint ID when none is supplied and preserves caller descriptions.

Slider now supports controlled value/onChange or onValueChange, uncontrolled defaultValue, showValue/formatValue, native refs, helper/error content and form reset. The track/knob use native range interaction, short focus/press feedback and logical RTL filling; readOnly blocks pointer/keyboard edits. RangeSlider supports independent controlled low/high or defaultLow/defaultHigh, lowName/highName/form, individually named thumbs, dependent ARIA bounds, track click and native reset. Values clamp to finite bounds and the minimum-anchored step grid; a low above high clamps down to high. Both thumbs retain DOM/Tab order. Browser/assistive touch behavior must still be checked on target devices ([WAI multi-thumb guidance](https://www.w3.org/WAI/ARIA/apg/patterns/slider-multithumb/)).

Stepper uses the shared explicit-label frame with named decrement/increment Buttons. It permits empty/intermediate drafts instead of coercing every keystroke, normalizes numeric values on blur or button press, steps relative to min (or defaultValue when unbounded), and disables step buttons for readOnly/disabled/boundary states. Uncontrolled empty drafts remain empty; controlled empty drafts restore the committed value on blur. Native number constraints and Arrow keys remain available. Slider/Stepper wrapperProps follow the new outer-div contract; native className/style/ref target the input. Reset synchronization runs once after the native reset action, skips prevented resets and cleans up on unmount. No numeric animation frame loop is used.

Checkbox keeps its native input, label/Space interaction, controlled/uncontrolled state, and form reset behavior. `Checkbox.tsx` drives a 320ms circular fill/unfill ripple through the Web Animations API, revealing/retracting the checkmark with it (no CSS transitions). The fill expands to a 100% radius and is clipped by the outer checkbox, avoiding inset rounded-corner gaps. Rapid toggles continue from the visible radius; initial render is not animated. Reduced-motion preferences skip ripples; forced-colors mode restores the system checkbox indicator. `className` and `style` still target the input.

Toggle uses a native checkbox with switch semantics, a logically translating RTL-aware thumb, native refs and separately associated label/description. className retains its decorative-track target; use classNames.input for the native input and wrapperProps for its label. Forced colors shows the system checkbox instead of a decorative track.

RadioGroup and SegmentedPicker support controlled `value` or uncontrolled `defaultValue`; controlled radios do not also receive a `defaultChecked` prop. Both accept helperText/error, required, native fieldset refs/form/disabled, part classes and readable empty states. Native radios retain Tab/Space/arrow selection and submit/reset behavior. SegmentedPicker's single decorative layer travels by transform/scale, retargets from its current visual position and removes finished animations. Boundary-only geometry reads and scoped resize/ancestor-appearance observers keep it aligned in narrow/RTL layouts; all observers/listeners/effects are removed on unmount. Reduced motion and forced colors restore CSS checked-state selection with no travelling layer. System Highlight/HighlightText are explicitly preserved to avoid forced-color text backplates.

Checkbox forwards a native ref, cancels active effects when accessibility preferences change, handles prevented resets and restores controlled indeterminate state on rerender. Unsupported pseudo-element animation falls back to the native final state. The reduced-motion CSS cascade still applies no transitions to the checkbox/checkmark.

Combobox, ColorPicker and FilePicker also use the shared outer-div field frame, explicit labels, helper/error/adornment parts and native refs. Combobox is editable: Arrow keys explore enabled suggestions while DOM focus stays on the input; Enter chooses, Escape restores the typed draft, Tab leaves normally, and text-editing keys are not intercepted. IME confirmation is not selection. Filtering reads nested text labels or InputOption.textValue (use it for custom/rich components), and matches the value. autocomplete="none" shows all suggestions; "list" filters; "both" additionally displays/selects a matching value's suffix and accepts it once on Enter, Tab or outside blur. Deletion does not reinsert the suffix; controlled parents may reject changes. Native form/reset/readOnly/disabled behavior is retained, with interruptible opening and retained closing motion; suggestions remain stable during exit. See the [WAI combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

FilePicker has one native file-selection trigger and an explicitly associated label, not a second imitation button. maxSize is finite nonnegative bytes per file: an oversized selection clears the actual FileList, sets native custom validity and displays an associated error. A valid retry/reset clears that error; cancel preserves the prior selection and optionally emits onCancel with the native event. onFilesChange reports selections/rejections, not native resets; consumers owning extra form state should handle Form.onReset. accept/capture/multiple/name/form/required remain native. Files never upload automatically; browser filtering and client size checks do not replace server-side validation ([native file input](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)).

DatePicker now enhances mode="date" with a custom single-date calendar; time and datetime-local modes remain native. The server and first hydration render keep the original native date input, so no-JS forms still work. After hydration, a formatted, labeled Button opens a nonmodal keyboard calendar; the original input remains the native ref/form/constraint owner but is visually and accessibility-hidden. ISO YYYY-MM-DD values never become instants or change timezone. Gregorian month/day names and localized numerals use Intl; no alternate-calendar date arithmetic is implied.

Locale priority is explicit locale (including a caller's saved app/user preference), then navigator.languages/navigator.language, then fallbackLocale (default en-US). Browser preferences are read after hydration and refreshed on languagechange. preferClientLocale={false} opts out. Malformed/unsupported locales fall back safely. Nothing reads/writes persistent storage or changes browser/OS settings. Native time/datetime UI and native validationMessage use browser-owned language/format, not an emulated clock or translated parser.

Built-in calendar/action/help messages cover English, Italian, French, German, Spanish, Arabic and Japanese; other Intl locales still format dates but fall back to English control copy. messages (DatePickerMessages) overrides any copy for application translations. Intl.Locale week information determines the first weekday (with a compatibility fallback); weekStartsOn={0..6} overrides it. Locale direction and number formatting support RTL; native dir can override direction.

value/onChange and defaultValue/reset remain native; onValueChange(value) is an additional ISO-string callback. Selection, Today and Clear update the native field once; controlled parents may reject a change. Native min/max/step/required/form/disabled/fieldset/readOnly remain authoritative; invalid submission announces the native validation message and opens correction UI. Clear is unavailable for required fields. Read-only fields can focus without opening. Reopening anchors the selected value or the client's current day. Arrows, Home/End and Page Up/Down (Shift for years) move a roving focus; Enter/Space selects, Escape restores trigger focus, outside press/Tab dismisses without stealing outside focus. The manual Popover API keeps the popup above clipped containers and retains it until its closing effect settles; unsupported browsers get a positioned nonmodal fallback. Positioning reads geometry only on open/resize/scroll, not an animation frame loop. Shared motion tokens/reduced-motion/forced-color fallbacks apply.

className/style/ref still target the native input. Use classNames.trigger/panel for the new surfaces and existing field part classes/wrapperProps for layout. The custom date surface is calendar selection rather than free-form localized text parsing; time/datetime-local editing is unchanged. Focus is transferred off the native fallback when enhancement activates. See tests/date-picker.verify.mjs and tests/date-picker.browser.tsx for locale, form, keyboard, hydration and fallback coverage.

 ColorPicker exposes a native opaque sRGB input, optional showValue (default true), normalized six-digit hex text and native form/reset behavior. readOnly blocks picker activation; allowAlpha is compatibility-only and does not enable unsupported alpha/gamut features. Actual OS color/file pickers remain browser-owned.

MultiDatePicker now presents a bounded six-week calendar with month controls, full weekday/date names, one roving date Tab stop and independent multi-selection across months. It uses shared Buttons, date-only Gregorian arithmetic (no instant/timezone conversion), dependent min/max limits, Space/Enter selection, logical arrows, Home/End and Page Up/Down (Shift for years), with short month entrance motion. selected/onSelectedChange is controlled; defaultSelected is uncontrolled. Optional name emits one hidden native value per selected ISO date, including off-screen months; form/fieldset disabling and prevented reset work natively. readOnly permits browsing without changing selection. Reset restores uncontrolled defaults and the initial anchor; invalid/duplicate/out-of-bounds dates are excluded. initialMonth (YYYY-MM), locale (default en-US) and weekStartsOn (0/1, default Monday) control presentation. Supply initialMonth or a bound/selection for a deterministic prerendered calendar. An unanchored SSR render deliberately shows readable initialization text, then chooses the browser's local month after hydration, avoiding a server-clock mismatch. The [WAI date-grid guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/) informs keys/focus, not an assistive-device certification; this is an inline multiselect calendar, not that example's modal single-date control.

Button keeps native button/ref/type/submit/reset and unstyled direct-child contracts. onPress may return a Promise: pending prevents duplicate activation and loading=false does not override actual pending work. Rejections call onPressError; without a handler, a generic associated alert/outline permits retry without leaking the error payload. Synchronous actions do not flash a loading spinner. Focus returns after pending only when it would otherwise be stranded on the document body. longPress is a pointer-hold enhancement for onPress; keyboard/assistive activation remains standard. Hold feedback scales a layer rather than animating width, cancels on release/leave/cancel/disabling/prop change/unmount and retains the delayed event's currentTarget. Validation-dependent work belongs in Form.onSubmit, not a button click handler; no async action is automatically retried or aborted by this library.

RenameButton never nests a form. It opens a selected current-name draft, trims/validates on Save/Enter, cancels on Escape/Cancel, and optionally commits on leaving the entire editor (commitStrategy="blur"). Internal focus and Cancel do not commit. Async failure preserves the draft with recovery feedback; save/cancel are locked while a commit runs because the component cannot undo caller side effects. Success/cancel returns focus without overriding a user's new outside focus. Controlled value is refreshed on every open. Native form reset restores uncontrolled defaults when idle; a pending commit is not falsely presented as cancelled.

PasteButton reads only on activation, honors the requested text/html format order, and supplies onPasteEvent(value, format). HTML is untrusted source text and is never executed or inserted. Empty/unavailable/denied/callback-failure states are distinct; pending blocks duplicate reads. ShareLink validates the native payload/canShare capability, resolves relative URLs, communicates unsupported files and distinguishes user cancellation. Its fallback is explicit: no automatic clipboard write or file dropping. Copy link/text is a separate button; a read-only selectable value remains when copying fails/is unavailable. Browser permission/activation/security/OS behavior still applies ([Clipboard API](https://www.w3.org/TR/clipboard-apis/), [Web Share](https://www.w3.org/TR/web-share/)). Tests use scoped API mocks, not real user clipboard/share targets.

ProgressView and Gauge keep explicit native progress/meter labels/refs and optional showValue/formatValue. Values/bounds/thresholds are finite and clamped; omitted/nonfinite progress value is indeterminate, and Gauge tone="auto" reflects low/high/optimum regions (explicit accent/success/warning/danger overrides are supported). Both retain their label wrapperProps contract and native className/style targets; classNames.track/fill/value customize the decorative surface. Determinate fill updates use short transform-only motion. Indeterminate progress uses one repeating compositor effect, paused offscreen, under hidden/inert ancestors and in a background document; preference changes cancel it and unsupported APIs leave a static working state. Observers/listeners/effects clean up. Reduced motion is static and forced colors restores native indicators. No progress percentage is invented for an indeterminate task.

Form and ControlGroup retain native form/fieldset refs and semantics; group disabling affects native controls, not anchors. Compose pending/validation with named fields and a disabled ControlGroup as needed, not nested forms or fake submission. LabeledContent remains dl/dt/dd, wraps long values and reflows on narrow screens; it does not automatically label a separate form control. HelpLink remains a native anchor, protects/announces new-tab destinations, and explicitly honors aria-disabled by omitting navigation and Tab access. Native hidden is respected despite appearance classes (hidden="until-found" is left to the browser). FieldGroup/RangeSlider also forward native owner refs. See ../README.md for shared tokens/density scopes.

## Custom Picker and popup lifecycle

Picker now uses a custom, animated combobox Button/listbox after hydration, for both single and multiple selection. Its original select remains the native form/ref/required/value/defaultValue/multiple/onChange owner and the visible SSR/no-JS fallback. Selection commits emit one native change event; controlled parents may reject them. Uncontrolled reset follows native defaults, controlled reset restores the supplied selection, and prevented resets are ignored. Multiple choices toggle without closing; single choice closes. Optional readOnly blocks custom edits, and disabled options/fieldsets/inert controls cannot be selected.

Arrows, Home/End, Enter/Space, Escape, Tab, typeahead and active-option scrolling are provided; focus stays on the trigger with an active descendant. Empty lists and native validation failures have readable messages. Values must be unique and labels noninteractive; textValue supplies native fallback/typeahead text for rich labels. classNames.trigger/panel/option customize the new surfaces; className/style/ref and native handlers target the real select, while wrapperProps targets the outer field. Native size is used as an approximate popup-height cap (one to twelve rows), not an OS list request. The live example demonstrates controlled single choice, uncontrolled multiple choice and native reset.

Combobox, DatePicker and Picker share openingAnimation/closingAnimation (both default true), retained exit presence and trigger-origin scale/fade. Closing updates logical expanded state immediately and makes the retained popup inert, aria-hidden and pointer-inactive. DatePicker/Picker use manual native popovers with owned light-dismiss so exits complete before top-layer removal. Reversals continue from current appearance; reduced motion, forced colors, page hiding, zero duration and unavailable WAAPI settle immediately. Actual unmount still removes the surface immediately. No JS frame loop, animated dimensions/blur or exit timer is used. See [the popup inventory](../../../../../swiftui-web-component-blueprint/POPUP-ANIMATION-AUDIT.md) for all owners, OS-owned exceptions and typecheck-only verification.
