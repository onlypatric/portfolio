# Team dashboard

- URL: `/ohmygui/examples/team-dashboard`; entry: `../../team-dashboard.astro`.
- Prerendered static page using BaseLayout; no adapter-specific request behavior.
- UI owner: `../../_components/team-dashboard/index.astro`, rendering a `client:load` React island directly. No NavigationSplitView or catalog shell; the dashboard is fixed to the dynamic viewport with no document or view-level scrolling.
- The four-tab selector is centered over the content at the bottom with safe-area spacing; the surrounding area is transparent and the dock uses a 48% material tint with 28px backdrop blur (with the library’s opaque fallback for unsupported/reduced-transparency/forced-color modes). Content has bottom clearance to keep its final controls accessible; it remains visible while content scrolls. Each view keeps its heading stationary and uses a labeled, keyboard-focusable OhMyGUI ScrollView for overflow. Chat additionally scrolls its message log, with the composer retained in the conversation card; on smaller/shorter screens the inner chat workspace scrolls to keep all controls reachable.
- Interface uses OhMyGUI components with a scoped warm/forest palette, layered surfaces, colored initial avatars and a material bottom dock. Recharts supplies responsive activity/workload charts and metric sparklines, kept behind hydration-safe placeholders. TabView, Stagger and the presentation components use existing motion and accessibility behavior, including reduced motion.
- Home includes comparable weekly activity/workload modes, metric sparklines, a sprint progress feature, clickable priority tickets, teammates and a contribution goal. Sprint counts derive from local tickets; current and previous activity periods have distinct comparison data.
- Chat has a channel directory, teammate presence, pinned ticket context, message bubbles and a composer; it scrolls to the latest message after sending/channel selection. Tickets has clickable status summaries, an animated segmented filter, search, an OhMyGUI Table (ID sorting and per-row status actions), and a retained Dialog for ticket creation with project/priority fields.
- Settings includes a workspace identity card, labeled fields, notification rows, default-view selection and save feedback. Workspace edits update the header; status changes, creation and saving produce dismissible OhMyGUI Toast feedback above the dock.
- The header’s CommandPalette opens via its search button or Command/Control K and searches views, tickets and teammates. The profile Popover links to Settings. Neither search nor profile actions make network requests.
- State stays local to the island, survives tab changes and resets when leaving/reloading. No network requests, authentication, backend or message delivery.
- The shared OhMyGUI preferences facade applies saved theme/density synchronously before page content, preventing a conflicting first paint. Invalid/unavailable storage uses light/comfortable. This page inherits the palette and does not write preferences.
- Initial HTML includes the Home view and chart totals; responsive charts render after hydration. Controls require JavaScript.
- The Examples catalog links here through native navigation, and the dashboard header links back to Examples. Chart/dashboard code is loaded only on this page.
