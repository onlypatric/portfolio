# Team dashboard

- URL: `/ohmygui/examples/team-dashboard`; entry: `../../team-dashboard.astro`.
- Prerendered static page using BaseLayout; no adapter-specific request behavior.
- UI owner: `../../_components/team-dashboard/index.astro`, rendering a `client:load` React island directly. The top-level AppFrame remains a standalone dashboard shell; Settings embeds a NavigationSplitView. The dashboard is fixed to the dynamic viewport with no document scrolling.
- The four-tab selector is centered over the content at the bottom with safe-area spacing; the surrounding area is transparent and the dock uses a 48% material tint with 28px backdrop blur (with the library’s opaque fallback for unsupported/reduced-transparency/forced-color modes). TabView measures dock clearance and shares it with AppFrame feedback positioning; content uses that clearance to keep its final controls accessible; it remains visible while content scrolls. Home/chat/tickets keep stationary headings and labeled OhMyGUI scrolling regions. Settings fills the entire dashboard content area directly with split panes, without an introductory heading or outer content gutters. Chat additionally scrolls its message log, with the composer retained in the conversation card; on smaller/shorter screens the inner chat workspace scrolls to keep all controls reachable.
- Interface uses OhMyGUI components with the scoped Modern preset (neutral surfaces, blue accent, conventional green/red/yellow statuses and independently colored paper/contrast/solid panels), layered surfaces, colored initial avatars and a material bottom dock. Recharts supplies responsive activity/workload charts and metric sparklines, kept behind hydration-safe placeholders. TabView, Stagger and the presentation components use existing motion and accessibility behavior, including reduced motion.
- Home includes comparable weekly activity/workload modes, metric sparklines, a sprint progress feature, clickable priority tickets, teammates and a contribution goal. Sprint counts derive from local tickets; current and previous activity periods have distinct comparison data.
- Chat has a channel directory, teammate presence, pinned ticket context, message bubbles and a composer; it scrolls to the latest message after sending/channel selection. Tickets has clickable status summaries, an animated segmented filter, search, an OhMyGUI Table (ID sorting and per-row status actions), and a retained Dialog for ticket creation with project/priority fields.
- Settings embeds a height-bounded NavigationSplitView with General information, Privacy & security, and Aspect preferences navigation. General keeps identity/contact, notifications and default-view controls. Security policies/visibility are local previews, without real authentication or analytics. Appearance changes palette, mode, density and tab animation quality live, with a restore-defaults action. Workspace edits update the header; status changes, creation and saving produce dismissible OhMyGUI Toast feedback above the dock.
- The header’s CommandPalette opens via its search button or Command/Control K and searches views, tickets and teammates. The profile Popover links to Settings. Neither search nor profile actions make network requests.
- State stays local to the island, survives tab changes and resets when leaving/reloading. No network requests, authentication, backend or message delivery.
- The shared OhMyGUI preferences facade applies saved theme/density synchronously before page content, preventing a conflicting first paint. Invalid/unavailable storage uses light/comfortable. The page initially inherits saved mode/density, then permits session-local appearance overrides without writing stored showcase preferences.
- Initial HTML includes the Home view and chart totals; responsive charts render after hydration. Controls require JavaScript.
- The Examples catalog links here through native navigation, and the dashboard header links back to Examples. Chart/dashboard code is loaded only on this page.

- Production hydration imports the dashboard’s entire dependency graph. A cached 404 for a shared chunk prevents loading even if the dashboard entry returns 200. Site-wide `public/_headers` requires asset revalidation; previously cached immutable failures require a cache-bypassing reload once. See `src/_docs/README.md` for delivery policy.

- Presentation comes from ThemeScope, AppFrame, ContentRegion, Surface/Card, responsive Grid/Stagger, Text roles, Row, MetricSummary, AvatarGroup, Gauge ring and density/placement props. The former 25,004-byte stylesheet (751 declarations / 272 rules) is deleted; no custom classes, inline styles or application CSS remain in the dashboard/chart consumer graph, aside from separately baselined pre-existing site foundations.
- Source gate: `npm run check:styles`; shared authoring/API/browser-check guidance lives under `src/ohmygui/_docs/design-system/`. Browser visual/interaction acceptance is deferred; type/build/audit results are in the changelog.

- Home explicitly mixes surface treatments: success/paper/contrast/neutral metrics, a light paper chart, contrasting sprint and solid success-colored team panel. Surface/Card own paired typography, controls and chart tokens; this is per-component composition rather than one global color applied everywhere. Workspace is unchanged.

- TabView starts with animationQuality enhanced; the Aspect preferences picker can choose auto/basic/enhanced. Browser support and accessibility gates still apply.
- Settings renders NavigationSplitView viewport=false directly as its tab content, filling the available width/height beneath the shared app bar. Both split panes scroll independently with automatic bottom-dock scroll clearance; below 720px the Sections button opens a sidebar contained within Settings, leaving the app bar/dock and surrounding UI usable. Its close control/Escape returns to Preferences, and choosing a category closes the menu and reveals its content. Destination motion uses contentTransitionKey; section, pane, drafts and preferences live in the dashboard state and survive main-tab changes.

- Aspect preferences offers Modern, Ember, Orchid, Monochrome and Studio. Modern is also the restore-defaults palette.
